# Development notes

Detailed notes retained from the original Russian README and updated for saved
profiles and microphone preflight. See the [English overview](../README.md) first.
These notes describe implementation and test coverage, not verified provider or
physical-headset compatibility. No public binary release or notarization exists.


Нативный SIP-софтфон для macOS на **SwiftUI + PJSIP**: подключение к вашей АТС,
входящие и исходящие голосовые звонки. Без браузера, Electron, облачного
посредника, телеметрии и обязательных сторонних аккаунтов.

Это самостоятельный MVP с основными функциями Zoiper, **не копия Zoiper и не
полная замена всех его возможностей**.

## Возможности

- Tray-версия: тёмная минималистичная панель **360 × 580 pt**, без Dock-иконки
  и большого окна при запуске. Нажмите телефон в строке меню: «Набор», «История»,
  «Настройки». Входящий звонок автоматически открывает панель ответа.
- Несколько сохранённых SIP-профилей, одна активная линия: сервер, порт, SIP-логин, отдельный auth ID, пароль, display name,
  outbound proxy; регистрация Digest, автоматическое обновление регистрации.
- SIP по **UDP / TCP / TLS**, IPv4 и явно заданный IPv6.
- Входящий вызов со звуковым сигналом и кнопками «Ответить» / «Отклонить»;
  исходящие на номер, extension или SIP URI.
- Двусторонний RTP, **G.711 μ-law, G.711 A-law, G.722**, эхоподавление Speex.
- Mute, удержание / продолжение, DTMF через **RFC 4733 / RFC 2833 или SIP INFO**.
- **SRTP/SDES**: отключён, опциональный или обязательный. Включается только с TLS,
  чтобы ключи SDES не уходили по незашифрованной сигнализации.
- Выбор микрофона и динамиков, системные устройства по умолчанию.
- Восстановление локального аудиоустройства после изменения системной громкости,
  маршрута или остановки playback callback. Изменения объединяются с задержкой
  350 мс; переоткрывается только AudioUnit, не SIP/RTP-сессия. Mute и удержание
  сохраняются. При повторных ошибках попытки восстановления ограничены.
- До 200 локальных записей истории: состоявшиеся, пропущенные, отклонённые,
  отменённые и неуспешные звонки.
- Режим «Не беспокоить», восстановление регистрации после сна.
- `sip:`, `sips:` и `tel:` ссылки **только заполняют поле набора**; звонок требует
  отдельного нажатия. Входящие REFER, Replaces и автоматические SIP-редиректы
  отклоняются: удалённая сторона не может сама запустить новый исходящий звонок.

## Сборка и запуск

Нужны macOS, Xcode / Command Line Tools, Swift 6+, `make`, `curl` и Python 3.
Homebrew, CocoaPods, CMake и OpenSSL для сборки не нужны. Deployment target —
**macOS 14.0**; бинарник собирается под архитектуру текущего Mac.

```sh
cd SipDesk
./build.sh --run
```

Результат: `build/SIPDesk.app`. Скрипт **не устанавливает приложение в
`/Applications`**, не завершает чужие процессы и не подключается к SIP-серверу.
`--run` только открывает собранное приложение. Без этого флага выполняется сборка.

Чтобы подготовить обновление, не закрывая работающий экземпляр:

```sh
SIPDESK_OUTPUT_DIRECTORY="$PWD/build/alternate" ./build.sh
```

После завершения текущего звонка выйдите из старого SIPDesk и откройте новую
сборку. Настройки аккаунта и Keychain общие; одновременно запускать два экземпляра
с одной SIP-линией не следует.

```sh
./build.sh
./build.sh --debug
./Scripts/test.sh
```

Первая сборка скачивает PJSIP с GitHub, проверяет SHA-256 и собирает статическую
библиотеку. Последующие используют `.dependencies/pjsip`. Для разработки в Xcode
сначала выполните `./Scripts/bootstrap-pjsip.sh`, затем откройте `Package.swift`.
Для реальных звонков запускайте именно `.app`, а не `swift run`: bundle содержит
назначение доступа к микрофону и нужные ресурсы.

По умолчанию подпись ad-hoc. Можно указать **уже установленный** signing identity:

```sh
SIGNING_IDENTITY="Your existing signing identity" ./build.sh
```

Скрипт не создаёт сертификатов и не меняет хранилище доверия. При ad-hoc-подписи
после пересборки macOS может снова запросить доступ к микрофону / Keychain.
Нотаризация и публичная дистрибуция пока не настроены.

## Первое подключение

1. Нажмите телефон в строке меню → **«Настроить SIP-линию»**
   (или «Настройки» → ваша линия).
2. Укажите адрес сервера **без `sip://`, пути и порта**: например `pbx.example.com`
   или `192.168.1.20`. Порт задаётся отдельным полем. IPv6 — `[2001:db8::10]`.
3. Укажите логин, например `1001`, и SIP-пароль. Не вводите `1001@server` в поле логина.
4. Выберите транспорт, который предоставляет АТС. Часто UDP/TCP используют 5060,
   TLS — 5061, но решающими являются настройки вашего сервера.
5. Если auth ID отличается от логина, заполните его в дополнительных настройках.
   Там же находятся outbound proxy, STUN, ICE, SRTP и DTMF.
6. Сохраните с флагом **«Подключиться после сохранения»**. Дождитесь статуса **«На связи»**.
7. Введите внутренний номер, обычный номер или `sip:1002@pbx.example.com` и нажмите
   **«Позвонить»**. До звонка разрешите микрофон в «Настройках» SIPDesk;
   во время набора или ответа системный диалог разрешения не открывается.

Не присылайте SIP-пароль в чат и не сохраняйте его в исходниках. Введите его
непосредственно в приложение.

Закрытие панели **не завершает** SIPDesk: входящие продолжают поступать, пока
приложение работает. Чтобы отключить линию, выберите «Не в сети» в меню статуса или выйдите
из приложения кнопкой питания справа внизу панели. Во время активного звонка выход
требует подтверждения. Компьютер должен бодрствовать и иметь доступ к сети;
пуш-вызовов при выключенном приложении нет.

## Безопасность и данные

- SIP-пароль хранится только в **macOS Keychain**, service `local.sipdesk.accounts`.
  Он не входит в JSON, историю, логи или репозиторий. В оперативной памяти пароль
  необходим SIP-движку для авторизации.
- Настройки и история: `~/Library/Application Support/SIPDesk/`. Каталог имеет
  права `0700`, JSON — `0600`, запись выполняется через атомарную замену.
  JSON-файлы не зашифрованы; история содержит номера и идентификаторы абонентов.
- Микрофон не открывается для регистрации и ожидания входящего. Вызовы не записываются.
- TLS использует Apple Network.framework и **проверяет сертификат сервера**.
  Кнопки «игнорировать сертификат» нет. Для АТС с частным CA доверие должно быть
  настроено администратором в macOS; приложение не устанавливает CA.
- UDP/TCP + RTP не шифруют сигнализацию и звук. TLS сам по себе не шифрует RTP.
  Выбирайте TLS + обязательный SRTP, если АТС это поддерживает, либо подходящий VPN.
- STUN по умолчанию отсутствует, ICE выключен. Никакие публичные STUN-сервисы
  не зашиты в приложение. При смене аккаунта SIP-движок пересоздаётся, чтобы не
  сохранялись настройки STUN, сокеты и credentials предыдущего подключения.
- Определитель номера — данные SIP-сервера, а не доказательство личности звонящего.
- Диагностика содержит только события текущего запуска, без дампов SIP/SDP и секретов.

### Версия SIP-движка

Используется зафиксированный upstream snapshot **PJSIP 2.17-dev**:
`c7fa6bfb85172f038cf37986696a16b3987391ea` от **21 октября 2026 года**.
Это не плавающий `master` и не заявление о stable-релизе.

Причина: после релиза 2.17 опубликованы исправления уязвимостей SIP/SDP, DNS,
TLS и времени жизни объектов; upstream включил их в ветку разработки.
SHA-256 архива, лицензии и ссылки на advisories указаны в
[`THIRD_PARTY_NOTICES.md`](../THIRD_PARTY_NOTICES.md).

## Проверки

`./Scripts/test.sh` не обращается к настоящей АТС, не использует реальные пароли,
не совершает платных звонков и не записывает микрофон:

- Swift Testing: валидация SIP URI, номера и IPv6; защита от CR/LF/NUL и SIP-header
  injection; согласованность транспорта; запрет SRTP/SDES поверх plaintext SIP;
  JSON без пароля; права файлов; сохранность повреждённых файлов; классификация звонков.
- Runtime: PJSIP работает на собственном постоянном потоке, события идут по
  упорядоченному `AsyncStream`, запуск/остановка повторяемы, команды после остановки отклоняются.
- Python stdlib + `SIPProbe`: локальный Digest registrar для UDP/TCP; неверный пароль;
  REGISTER/Expires:0; два настоящих PJSIP клиента с входящим/исходящим вызовом,
  RTP, DTMF обоих типов, mute, hold/resume, busy, CANCEL, decline, BYE; IPv6.
- TLS: локальный сервер с временным недоверенным сертификатом. Клиент обязан
  отклонить его до отправки REGISTER. Тест не добавляет сертификат в Keychain.

Эти проверки **не заменяют проверку на вашей АТС**. Доступ к реальному SIP-серверу,
NAT конкретной сети, физическая слышимость/эхоподавление на выбранной гарнитуре,
а также совместимость TLS/SRTP с конкретным провайдером требуют отдельного пробного
звонка после ввода ваших настроек.

Предпросмотр интерфейса без сети и Keychain:

```sh
build/SIPDesk.app/Contents/MacOS/SIPDesk --preview
build/SIPDesk.app/Contents/MacOS/SIPDesk --render-preview "$PWD/build/interface.png"
```

Проверка packaged UI выполняется локально, в графической сессии macOS:

```sh
SIPDESK_TEST_APP="$PWD/build/SIPDesk.app" python3 -m unittest discover -s Tests/Integration -p test_tray_ui.py -v
```

## Структура

```text
Sources/SIPCore/      модели, SIP URI, локальное хранилище
Sources/SIPBridge/    C-обёртка над PJSUA, очередь событий, аудио и управление звонком
Sources/SIPRuntime/   постоянный SIP-поток, AsyncStream, проверка токенов звонка
Sources/SIPDesk/      SwiftUI, состояния звонка, Keychain, история и lifecycle macOS
Sources/SIPProbe/     headless SIP-клиент для loopback-тестов
Resources/           Info.plist, entitlement, генераторы иконки и звуков
Tests/               unit, runtime и сетевые integration-тесты
Scripts/             воспроизводимая сборка SIP-движка и тесты
```

Все вызовы PJSUA выполняются на одном постоянном потоке. Нельзя заменять его
обычной serial GCD queue: она не гарантирует постоянство pthread. Callback-и C
передают снимки состояния через очередь; SwiftUI изменяется только на MainActor.
Каждый звонок имеет монотонный token: отложенная команда не может случайно
управлять следующим звонком с переиспользованным PJSIP ID. Разрешение микрофона
запрашивается отдельно в настройках до звонка, не при наборе или ответе.

## Границы MVP

Несколько сохранённых профилей, одна активная линия и один активный звонок; второй входящий получает Busy и остаётся в
истории как пропущенный. Пока нет одновременно подключённых линий, трансфера, конференций,
видео, записи разговоров, адресной книги, BLF/presence, G.729, Opus, TURN,
автообновления, запуска при входе в macOS и App Store distribution.
